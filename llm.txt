# LLM Codebase Briefing (Detailed)
Last updated: 2026-01-28

Instruction: Update this file whenever a codebase edit changes behavior, structure, public APIs, outputs, or schemas.

## Repository purpose
- Parse Italian payroll PDFs (cartellini) and timbrature reports generated by Azienda Ospedaliera di Perugia / INSIEL.
- Normalize data into pandas DataFrames, validate totals, and emit CSV/JSON outputs.
- Scan Google Drive folders, build indexes, and fetch/parse documents in bulk.

## Top-level layout (by area)
- `src/cartellino_parser/`: cartellino-specific parsing pipeline + CLI.
- `src/timbrature_elenco_parser/`: parser for “elenco timbrature” layout.
- `src/timbrature_elenco_compact_parser/`: parser for compact timbrature layout.
- `src/timbrature_shared/`: shared timbrature parsing utilities (days, pairs, totals, header parsing).
- `src/parser_shared/`: shared models, text extraction, number parsing, validation, record -> DataFrame.
- `src/parser_service/`: auto-detection router that chooses cartellino vs timbrature parser.
- `src/drive_scanner/`: Google Drive scan/fetch, index schema utilities, logging, and helpers.
- `src/flatten_index.py`: utility to convert legacy index schemas into included/excluded index files.
- `tests/`: sample-based parsing tests for cartellino and timbrature.
- `samples/`: sample PDFs used by tests (cartellino/timbrature_compact/timbrature_elenco folders).
- `downloads/`, `output/`, `scan/`: operational output folders (not required for core parsing).
- `PARSING_SERVICE.md`: detailed parser service documentation.
- `CODEBASE_BRIEFING.md`: concise overview for humans.

## Core data model
- Shared dataclasses live in `src/parser_shared/models.py`:
  - `DayRecord`: day-level metrics (year, month, day, dow, mo_f, mo_t, mo_lav, raw).
  - `PairRecord`: entry/exit pairs with timestamps and durations.
  - `ParsedCartellino`: `meta`, `days_df`, `pairs_df`, `totals`, `validation`.
- Errors:
  - `CartellinoParseError` base error for parsing.
  - `ParserDetectionError` for ambiguous/failed detection.

## Parsing flows (PDF -> outputs)
### Cartellino
- Entry point: `cartellino_parser.parser.parse_pdf` / `parse_text`.
- Text extraction: `parser_shared.extract.extract_text` (pdfplumber); if no day lines are detected, it retries with a vertical-text reconstruction from page characters.
- Meta parsing: `cartellino_parser.utils.parse_month_year` and `parse_employee`.
- Day parsing: `cartellino_parser.parse_days.parse_days` (regex day line + numeric tokens).
- Pair parsing: `cartellino_parser.parse_pairs.parse_pairs` (E/U events; keeps incomplete pairs; closest exit after entry, allowing next-day exit).
- Totals parsing: `cartellino_parser.parse_totals.parse_totals`.
- Validation: `parser_shared.validate.validate_cartellino` compares summed complete pair durations with `totals["ore_lavorate"]` when available.

### Timbrature (elenco + compact)
- Entry points:
  - `timbrature_elenco_parser.parse_pdf`
  - `timbrature_elenco_compact_parser.parse_pdf`
- Shared pipeline in `timbrature_shared.parser_base.parse_text_with`:
  - `timbrature_shared.utils.parse_month_year` and `parse_employee`
  - `parse_days` (variant-specific)
  - `timbrature_shared.parse_pairs.parse_pairs`
  - `timbrature_shared.parse_totals.parse_totals`
  - `parser_shared.validate.validate_timbrature` (tolerance 1.0 hour, when pair durations are available)
- Day parsing differences:
  - `timbrature_elenco_parser.parse_days`: uses `extract_day_values` + event presence.
  - `timbrature_elenco_compact_parser.parse_days`: uses numeric heuristics (values >= 1.0).
- Timbrature `mo_f`/`mo_t`/`mo_lav` are parsed but not used for validation or totals fitting.
- Timbrature pairs keep incomplete E/U rows and match closest exit after entry (allowing next-day exits).

### Auto-detection router
- Entry point: `parser_service.router.parse_pdf`.
- Detection logic:
  - `detect_document_family` scores cartellino vs timbrature via keyword hints + day line patterns.
  - `detect_timbrature_variant` distinguishes elenco vs compact via event density and value heuristics.
- `parse_pdf` only falls back to vertical-text reconstruction when both hint/day scores are zero; it does not fallback if hints are present.
- If parsing fails with no markers or no day lines, it retries with vertical-text reconstruction before failing.
- Strictness:
  - `PARSER_DETECT_STRICT=1|true|yes|on` forces strict decisions and raises `ParserDetectionError` on ambiguity.

## Outputs (per PDF)
- `days.csv` (or `*.days.csv` in cartellino CLI):
  - Columns: `year, month, day, dow, mo_f, mo_t, mo_lav, raw`.
- `pairs.csv`:
  - Columns: `year, month, day, dow, pair_index, entry_ts, exit_ts, duration_hhmm, turno, entry_raw, exit_raw`.
- `totals.json`:
  - Cartellino totals: `ore_lavorate`, `ore_dovute_programmate`, `ore_dovute_contrattuali`, `dbcr_lordo_confermato`, `dbcr_netto`, `saldo_al_mese_precedente`, `saldo_al_mese_corrente`.
  - Timbrature totals: `ore_dovute_programmate`, `ore_lavorate`, `flex`, `vestizione`, `da_autor` (when present).
- `report.json`:
  - `{ meta, totals, validation }`.

## Drive scanner (bulk processing)
### Environment and auth
- Env vars: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `DRIVE_ROOT_FOLDER_ID`.
- Token path: `GOOGLE_TOKEN_PATH` (default `token.json`).
- `drive_scanner.auth_service.load_creds` handles OAuth and token refresh; if refresh fails (e.g., revoked token), it falls back to interactive re-auth.

### Scan (build index)
- Entry: `drive_scanner.scan_directory:main`.
- Walks Drive folders, collects PDFs/ZIPs, excludes folders/files by terms in `drive_scanner.config.EXCLUDE_TERMS`.
- Output: `downloads/index.scan.json` by default (see `config.SCAN_REPORT_PATH`).

### Fetch/parse (consume index)
- Entry: `drive_scanner.fetch_index:main`.
- Loads `included.index.json` and `excluded.index.json` (pydantic `Index` model in `drive_scanner.index_service`).
- Downloads PDFs, auto-parses with `parser_service.parse_pdf`, writes outputs to:
  - `downloads/<employee>/<file_tag>/days.csv|pairs.csv|totals.json|report.json`.
- Output paths stored in indexes are relative to the `--out` directory (employee subfolder retained).
- Rewrites included/excluded index files periodically to reflect processing outcomes.

### Download raw PDFs (consume index)
- Entry: `drive_scanner.download_index:main`.
- Loads an index file and downloads raw PDFs to `downloads/<employee>/<file_name>__<id8>.pdf` (or flat with `--flat`).
- Skips entries with `reason` only when `--skip-reasoned` is set (default is to include them).

### Index schema (current)
- Pydantic models in `drive_scanner.schema`.
- `Index` model in `drive_scanner.index_service`:
  - `root_id`, `generated_at`, `employee_count`, `files[]`.
- `IndexFile` fields: `employee`, `employee_id`, `file_id`, `file_name`, `outputs?`, `reason?`, `type?`.
- `Outputs` fields: `days_csv`, `pairs_csv`, `totals_json`, `report_json`.
- `flatten_index.py` converts legacy index schemas into the current included/excluded format.

## CLIs and scripts
- Cartellino CLI: `python -m cartellino_parser.cli parse --input <DIR|FILE> --out <DIR>`.
- Parser service CLI (auto-detect): `python -m parser_service.cli parse --input <DIR|FILE> [--out <DIR>] [--recursive] [--strict] [--debug-detect] [--dump-text]`.
  - Output layout when `--out` is set: `out/<relative_path_without_ext>/days.csv|pairs.csv|totals.json|report.json` (preserves input subfolders).
  - Debug artifacts (when enabled with `--out`): `detect.normal.json`, `detect.vertical.json`, `extracted.normal.txt`, `extracted.vertical.txt`.
- Sample checker: `python -m parser_service.check_samples --samples samples --out samples/output --sample 0.7 [--limit N] [--extract-if-missing] [--diagnose-overcount] [--max-lines N]`.
  - Reports pair integrity issues for complete pairs (missing duration, duration mismatch); incomplete pairs are expected.
  - `tests/test_check_samples.py` generates outputs and runs full checks (no skipping).
- Drive scan: `python -m drive_scanner.scan_directory --root <FOLDER_ID> --out downloads/index.scan.json -v`.
- Drive fetch: `python -m drive_scanner.fetch_index --out downloads --included included.index.json --excluded excluded.index.json -v`.
  - Reason filters (excluded only): `--skip-reason`, `--skip-reason-contains`, `--skip-reason-regex` (repeatable).
  - Only-reason filters (excluded only): `--only-reason`, `--only-reason-contains`, `--only-reason-regex` (repeatable).
  - Output reuse: `--skip-existing-outputs` skips processing when all output files already exist.
- Download raw PDFs: `python -m drive_scanner.download_index --index <INDEX.json> --out downloads/raw -v`.
- Flatten index: `python src/flatten_index.py --input <OLD.json> --out-dir downloads`.
- Overtime analysis: `python -m drive_scanner.analyze_overtime --index <included.index.json> --output output/overtime_summary.json` (closes incomplete pairs within each file; configurable via `--close-gap-hours`; also writes `output/overtime_summary.csv`).

## Tests and samples
- `tests/test_samples.py`: sample harness across cartellino + timbrature + auto-detect (uses parser validation where available).
- `tests/test_timbrature_samples.py`: timbrature-only checks (days count 28-31, validation when available, pair duration consistency).
- `tests/test_check_samples.py`: wraps `check_samples` for full sample output verification.
- Samples expected under `samples/cartellino`, `samples/timbrature_compact`, `samples/timbrature_elenco`.

## Conventions and implementation notes
- Parser outputs must be DataFrames with explicit column ordering.
- Cartellino validation compares summed complete pair durations against `ore_lavorate` (tolerance 0.05, when available).
- Timbrature validation uses `validate_timbrature` (tolerance 1.0 hour, when available).
- Parser modules use `pathlib.Path`; drive modules use `os.path`.
- Logging: use `logging.getLogger(__name__)` in parsers and `drive_scanner.logging_utils` for CLI.
- Numeric parsing handles Italian decimals and HH:MM-style hours via `parser_shared.numbers`.
