# LLM Codebase Briefing (Detailed)
Last updated: 2026-01-30

Instruction: Update this file whenever a codebase edit changes behavior, structure, public APIs, outputs, or schemas.

## Repository purpose
- Parse Italian payroll PDFs (cartellini) and timbrature reports generated by Azienda Ospedaliera di Perugia / INSIEL.
- Normalize data into pandas DataFrames, validate totals, and emit CSV/JSON outputs.
- Scan Google Drive folders, build indexes, and fetch/parse documents in bulk.

## Top-level layout (by area)
- `src/parsing/`: parsing service + core framework; parser implementations live under `src/parsing/parsers/`, shared helpers under `src/parsing/parser_shared` and `src/parsing/timbrature_shared`.
- `src/drive_scripts/`: Google Drive scan/fetch/download utilities, index schemas, and helpers.
- `src/fetch_index_pipeline.py`: parallel download/parse pipeline (threads + processes).
- `src/process_extractions.py`: overtime summary + per-employee reports from included indexes.
- `convert_index_to_map.py`: convert legacy list index -> map index.
- `tests/`: sample-based parsing + drive utility tests.
- `samples/`: sample PDFs (cartellino/timbrature_compact/timbrature_elenco).
- `output/`, `scan/`, `downloads/`: operational output folders.

## Core data model
- Shared dataclasses in `src/parsing/parser_shared/models.py`:
  - `DayRecord`: day-level metrics (year, month, day, dow, mo_f, mo_t, mo_lav, raw).
  - `PairRecord`: entry/exit pairs with timestamps and durations.
  - `ParsedCartellino`: `meta`, `days_df`, `pairs_df`, `totals`, `validation`.
- Errors:
  - `CartellinoParseError` for parsing failures.
  - `ParserDetectionError` for ambiguous/failed detection.

## Parsing flows (PDF -> outputs)
### Cartellino
- Entry point: `parsing.parsers.cartellino.parse_pdf` / `parse_text`.
- Text extraction: `parser_shared.extract.extract_text` (pdfplumber); if no day lines are detected, it retries with `extract_text_vertical`.
- Meta parsing: `parsing.parsers.cartellino.utils.parse_month_year` and `parse_employee`.
- Day parsing: `parsing.parsers.cartellino.parse_days.parse_days`.
- Pair parsing: `parsing.parsers.cartellino.parse_pairs.parse_pairs` (keeps incomplete pairs; closest exit after entry; allows next-day exit).
- Totals parsing: `parsing.parsers.cartellino.parse_totals.parse_totals`.
- Validation: `parser_shared.validate.validate_cartellino` compares summed complete pair durations with `totals["ore_lavorate"]` when available (tolerance 0.05).

### Timbrature (elenco + compact)
- Entry points:
  - `parsing.parsers.timbrature_elenco.parse_pdf`
  - `parsing.parsers.timbrature_compact.parse_pdf`
- Shared pipeline in `timbrature_shared.parser_base.parse_text_with`:
  - `timbrature_shared.utils.parse_month_year` and `parse_employee`
  - `parse_days` (variant-specific)
  - `timbrature_shared.parse_pairs.parse_pairs`
  - `timbrature_shared.parse_totals.parse_totals`
  - `parser_shared.validate.validate_timbrature` (tolerance 1.0 hour, when pair durations are available)
- Day parsing differences:
  - `parsing.parsers.timbrature_elenco.parse_days`: uses `extract_day_values` and event presence.
  - `parsing.parsers.timbrature_compact.parse_days`: uses numeric heuristics (values >= 1.0).
- Timbrature `mo_f`/`mo_t`/`mo_lav` are parsed but not used for validation or totals fitting.
- Timbrature pairs keep incomplete E/U rows and match closest exit after entry (allowing next-day exits).

### Auto-detection router
- Entry point: `parsing.parser_service.router.parse_pdf` / `parse_text`.
- Detection logic:
  - `detect_document_family` scores cartellino vs timbrature via keyword hints + day line patterns.
  - `detect_timbrature_variant` distinguishes elenco vs compact via event density and value heuristics.
- `parse_pdf` uses vertical-text reconstruction when both family scores are zero, and retries vertical when parsing fails with "no markers" or "No day lines found".
- `analyze_detection` returns detailed score breakdown; `parsing.cli` can write `detect.*.json`.
- Strictness:
  - `PARSER_DETECT_STRICT=1|true|yes|on` forces strict decisions and raises `ParserDetectionError` on ambiguity.

## Outputs (per PDF)
- `days.csv` (or `*.days.csv` in cartellino CLI):
  - Columns: `year, month, day, dow, mo_f, mo_t, mo_lav, raw`.
- `pairs.csv`:
  - Columns: `year, month, day, dow, pair_index, entry_ts, exit_ts, duration_hhmm, turno, entry_raw, exit_raw`.
  - `entry_ts`/`exit_ts` are written as `YYYY-MM-DD HH:MM:SS` when outputs are saved.
- `totals.json`
- `report.json`:
  - `{ meta, totals, validation }`.

## Drive scripts (bulk processing)
### Environment and auth
- Env vars: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `DRIVE_ROOT_FOLDER_ID`.
- Token path: `GOOGLE_TOKEN_PATH` (default `token.json`).
- `drive_scripts.auth_service.load_creds` handles OAuth and token refresh (falls back to interactive auth on refresh failure).

### Scan (build index)
- Entry: `drive_scripts.scan_directory:main`.
- Walks Drive folders, collects PDFs/ZIPs, excludes folders/files by terms in `drive_scripts.config.EXCLUDE_TERMS`.
- Builds per-employee reports via `drive_scripts.scan_service.build_employee_report`.
- Writes index outputs via `drive_scripts.index_service.write_index_separated` (referenced by `scan_directory`).

### Fetch/parse (consume index)
- Entry: `drive_scripts.fetch_index:main`.
- Loads indexes with `MapIndex` (`drive_scripts.map_index_service`), allowing legacy list schemas via `--allow-legacy-index`.
- Downloads PDFs, auto-parses with `parsing.parse_pdf`, writes outputs to:
  - `downloads/<employee>/<file_tag>/days.csv|pairs.csv|totals.json|report.json`.
- Writes included/excluded map indexes; supports `--skip-existing-outputs`, `--skip-included`, `--reprocess-included`.

### Fetch/parse pipeline (parallel)
- Entry: `src/fetch_index_pipeline.py`.
- Uses a download thread pool + parse process pool with backpressure (`--max-in-flight`).
- Writes included/excluded map indexes and supports `--skip-existing-outputs`, `--skip-included`, `--allow-legacy-index`.

### Download raw PDFs (consume index)
- Entry: `drive_scripts.download_index:main`.
- Loads any index via `index_service.extract_index_files` (flat list).
- Downloads to `downloads/raw` (or flat with `--flat`), with options `--skip-reasoned`, `--include-non-pdf`, `--dry-run`, and `--report`.

### Index schema (current)
- `Index` model in `drive_scripts.index_service`:
  - `root_id`, `generated_at`, `employee_count`, `files[]`.
- `MapIndex` model in `drive_scripts.map_index_service`:
  - `root_id`, `generated_at`, `employee_count`, `total_files`, `files{file_id: IndexFile}`.
  - `allow_legacy=True` converts list-based `files[]` to map form.
- `IndexFile` fields: `employee`, `employee_id`, `file_id`, `file_name`, `outputs?`, `reason?`, `type?`.
- `Outputs` fields: `days_csv`, `pairs_csv`, `totals_json`, `report_json`.
- `convert_index_to_map.py` converts legacy list indexes to map indexes (default output: `<input>.map.json`).

## Overtime analysis
- `src/process_extractions.py` (`calculate_overtime`):
  - Reads included index (MapIndex), groups files per employee, loads `pairs.csv`, and closes incomplete pairs within `--close-gap-hours` (default 16.0).
  - Counts shifts exceeding `--hours` (default 6.0) and writes per-employee `output/<employee>/result.csv` + `report.json`.
  - Summary written to JSON + CSV (default `output/overtime_summary.json` / `.csv`).
  - Optional `--excluded` index adds broken/excluded counts and `broken_file_ids`.
  - Datetime parsing uses `pandas.to_datetime(format="mixed")` when available.

## CLIs and scripts
- Cartellino CLI: `python -m parsing.parsers.cartellino.cli parse --input <DIR|FILE> --out <DIR>`.
- Parsing CLI (auto-detect): `python -m parsing.cli parse --input <DIR|FILE> [--out <DIR>] [--recursive] [--strict] [--debug-detect] [--dump-text]`.
  - Output layout when `--out` is set: `out/<relative_path_without_ext>/days.csv|pairs.csv|totals.json|report.json` (preserves input subfolders).
  - Debug artifacts (when enabled with `--out`): `detect.normal.json`, `detect.vertical.json`, `extracted.normal.txt`, `extracted.vertical.txt`.
- Sample checker: `python -m parsing.parser_service.check_samples --samples samples --out samples/output --sample 0.7 [--limit N] [--extract-if-missing] [--diagnose-overcount] [--max-lines N]`.
- Drive scan: `python -m drive_scripts.scan_directory --root <FOLDER_ID> --out downloads/index.scan.json -v`.
- Drive fetch: `python -m drive_scripts.fetch_index --out downloads --index index.scan.json --included included.index.json --excluded excluded.index.json -v`.
- Fetch pipeline: `python src/fetch_index_pipeline.py --out downloads --index index.scan.json`.
- Download raw PDFs: `python -m drive_scripts.download_index --index <INDEX.json> --out downloads/raw -v`.
- Convert legacy index: `python convert_index_to_map.py <index.json> [--out <index.map.json>]`.
- Overtime summary: `python src/process_extractions.py --index included.index.json --output output/overtime_summary.json [--excluded excluded.index.json]`.

## Conventions and implementation notes
- Parser outputs must be DataFrames with explicit column ordering.
- Cartellino validation compares summed complete pair durations against `ore_lavorate` (tolerance 0.05).
- Timbrature validation uses `validate_timbrature` (tolerance 1.0 hour).
- Parser modules use `pathlib.Path`; drive scripts use `os.path`.
- Logging: parsers use `logging.getLogger(__name__)`; drive scripts use `drive_scripts.logging_utils`.
- Numeric parsing handles Italian decimals and HH:MM-style hours via `parser_shared.numbers`.
