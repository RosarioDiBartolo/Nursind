# Shared Logic Registry

Purpose: keep a single, agent-friendly inventory of reusable modules so new work extends shared code instead of duplicating it.

## Maintenance Rules
- Read this file before adding helpers to any CLI or feature script.
- If logic is reused by 2+ files, extract it into a shared module and add or update an entry here.
- Keep entries short and concrete: module path, what it owns, keywords or aliases, inputs or outputs, and where it is used.
- When replacing duplicated logic with a shared helper, note the old pattern under `Avoid Duplicates`.

## Avoid Duplicates
- Do not re-implement output path resolution in index runtimes; use `index_runtime.resolve_output_path`.
- Do not hardcode per-step output folder roots across scripts; use `src.pipeline_paths.build_pipelines_paths`.
- Do not hardcode notebook root ids, output roots, or per-step filenames in each notebook; use `src/notebooks/shared_config.py` with `src/notebooks/shared_config.json`.
- Do not re-implement mixed dict/object field reads for index items; use `index_runtime.doc_attr`.
- Do not re-implement index metadata refresh and periodic checkpoints; use `index_runtime.update_index_meta` and `index_runtime.maybe_flush_indexes`.
- Do not duplicate map/list index conversion logic in scripts; use `src.drive_service.index.converters`.
- Do not duplicate ZIP-member-aware index download flow; use `src.drive_service.index_downloads.download_pdf_bytes_for_index_item`.
- Do not re-implement PDF text extraction helpers; use `src.pdf_text_extraction`.
- Do not duplicate scan orchestration in CLI and notebooks; use `src.scan_directory.runtime.run_scan`.
- Keep CLI modules focused on argument parsing and orchestration; move reusable business logic into shared modules and register it here.
